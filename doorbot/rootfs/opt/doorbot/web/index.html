Motion & safety

Hold open retired

This used to drive past the unlocked point and hold the latch retracted so a passive outside handle could push the door open.

Removed for safety. Holding the latch means keeping the servo energised with nobody watching — a servo under torque cannot be turned by hand, so a fault during the hold can trap someone on the wrong side of the door. The firmware now releases torque at the end of every move, so this can no longer be sustained. Open now simply unlocks. If your door genuinely needs the latch held, say so and it can come back as an explicitly time-bounded mode.

PIN codes

PINs are stored hashed (PBKDF2-SHA256) — DoorBot can check a code but can never show it back to you.

SwitchBot Keypad

How this works. DoorBot’s ESP32 impersonates a SwitchBot Lock over Bluetooth. Your keypad pairs to it and sends every unlock as an AES-CTR encrypted message — the same protocol it would use with a real SwitchBot Lock. That message says how the credential was presented (PIN, fingerprint, NFC or face) and which slot it came from, so DoorBot knows exactly who is at the door.

Pair it once from the ESP32’s own setup page, then it is fully local. You do not need a SwitchBot Lock.
